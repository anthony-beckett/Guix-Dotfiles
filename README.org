#+TITLE: Guix Dotfiles
#+AUTHOR: Anthony J. Beckett

** Description
My personal GNU Guix SD configuration built around the ideas of functional programming. Planned using systems engineering techniques. My thoughts are: the GNU Guix configuration is truly software---not in some bizarre zoomed out view. It is software. Your configuration is a computer program. Therefore it ought to be truly considered as software and treated as such.

** On the Paradigm
Considering the use of Scheme, the overarching paradigm of this configuration is functional programming. Every "module" is a function. You can mix and match them. They take an operating system and they return an operating system. This is, unfortunately(/?/), done through a inheritance; a function takes an OS, creates a new one that inherits the given one, performs whatever that function ought to do, then returns it. Ultimately, a specific instantiation built around a specific system is made.

Freedom will be prioritised, but (/regrettably/) done away with when it seems impossible or implausible. Ideally, implemented via a toggleable module system.

** On Stability
Things will change drastically as I progress in my knowledge of GNU Guix and the Scheme programming language. So early on stability will not be a priority, though eventually it ought to be.
